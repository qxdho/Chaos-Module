# 26 · 马达音乐（S8）

> 独立实现，不使用 WavAudio 的源码、二进制或素材。只按公开的固件驱动行为重写。
> 目标：小米手环 10 Pro / 3.101.043。

## 它是什么

把 LRA（线性马达）当扬声器用：Chaos 通过 `/dev/lra0` 取得马达驱动对象，把
8-bit 单声道 PCM 送进马达芯片的 RTP/FIFO，马达线圈按音频波形振动。

```
/data/wav/*.s8
  → 读 12 kHz、单声道、signed 8-bit
  → 芯片 1: 12 kHz 直出；芯片 2: 2× 复制到 24 kHz
  → 马达驱动 FIFO（每次最多 256 B，查 busy 位）
  → PWM 电流 → LRA
```

它不是系统 `vibrate()`，不会调用固件的预设振动效果，也不改固件分区。

## 入口

主页 → 设置 → 震动 → **马达音乐**。

页面行：

| 行 | 功能 |
|---|---|
| 0 | 状态 / 曲目数 |
| 1 | 播放选中曲目 / 停止（第一次点只进入待确认，第二次才写寄存器） |
| 2 | 音量（20 → 40 → 70 → 100 循环） |
| 3 | 测试音（220 Hz，2 秒；同样两次点击确认） |
| 4..9 | 前 6 首 `.s8`，点击选中 |
| 10 | 重新扫描 |
| 11 | 返回 |

第一次播放/测试音前会做一次**只读探测**：打开 `/dev/lra0`、解析芯片并读一次 ID，
然后立刻关闭；不写任何寄存器。探测失败则直接返回错误，不会进入写寄存器阶段。

## 文件格式

只支持 `.s8`：

- 12 kHz
- 单声道
- signed 8-bit（`-128..127`）
- 无文件头

放到 `/data/wav/`，文件名以 `.s8` 结尾。安装器首次安装会创建 `/data/wav`；它也是原项目的音频目录，已有文件可直接复用。

生成示例（在电脑上）：

```bash
ffmpeg -i song.mp3 -ac 1 -ar 12000 -f s8 -acodec pcm_s8 song.s8
```

> `-f s8` 的输出就是无文件头 signed 8-bit；不同 ffmpeg 版本参数名可能不同，
> 用 `ffmpeg -formats | grep s8` 确认。

## 安全设计

1. **只在用户两次点击确认后写寄存器**，进入页面只读。
2. 打开后校验芯片编号（1/2）、基址对齐、ops 指针范围；不匹配立即放弃。
3. 修改前保存芯片 1 的 9 个 / 芯片 2 的 5 个寄存器，停止时写回。
4. 音量上限 100（映射到 0..200 的硬件增益），测试音幅度 48/127。
5. FIFO 满时只等待，不忙轮询；10 ms 定时器只在播放时启用，停止后降到 500 ms。
6. 读文件结束、FIFO 错误、页面退出都会 `stop()` 并恢复寄存器。

## 已知限制

- **没有真机验证**。这套寄存器序列来自固件驱动行为分析，不是 datasheet。
- 只支持 S8；MP3 解码、曲库封面、播放列表、进度条都未实现。
- 芯片 1 固定按 12 kHz 输出，芯片 2 固定 24 kHz。若某台 FS3002 实际是 24 kHz，
  S8 会以 2 倍速播放；后续应加“实测吞样率”校准。
- 马达不是扬声器：低频/节奏明显，中高频被机械系统滤掉，音质差是正常的。
- 播放时 UI 线程每 10 ms 被定时器唤醒一次，耗电会增加；停止后定时器降到 500 ms。

## 构建

```bash
cd projects/chaos
sh tools/build_ko.sh
python3 tools/build.py
```

本功能只改 Rust 模块和安装器，没有新增 C 源文件。若本机没有 Python，
可先只跑 `sh tools/build_ko.sh` 验证模块；完整容器打包仍需要 Python。

## 验证步骤（需要真机）

1. 安装新模块，重启。
2. 打开 设置 → 震动 → 马达音乐，看状态行是否显示曲目数。
3. 第一次点播放会先探测 `/dev/lra0`；若状态行报 `-102/-107`，说明驱动对象解析失败，
   先把页面/日志现象发回来。
4. 点“测试音”。正常应是 2 秒的低频“嗡——”，不是系统通知振动。
5. 放一首 `.s8` 到 `/data/wav/`，点“重新扫描”，选中，播放。
6. 若声音是 2 倍速/半速，记录芯片编号和现象；这需要加采样率校准。
7. 若出现异常振动、发热或停不下来，立即退出页面/重启；模块停止时会恢复寄存器。
